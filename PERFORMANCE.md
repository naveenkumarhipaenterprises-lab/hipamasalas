# Performance, accessibility & crawlability notes

How the site keeps its Lighthouse scores, and what to do when you add content.

## Images

* **Never reference a large original directly in a component.** Use `<ResponsiveImage>`
  (`client/src/components/ResponsiveImage.tsx`). It looks the original URL up in
  `client/src/lib/imageManifest.generated.ts` and emits `srcset`, `sizes`, `width` and `height`.
  Images without generated variants (e.g. a blog cover added via Google Sheets) still render
  from their original URL.
* **After adding or replacing an image in `client/public/assets/`**, add it to the matching list in
  `scripts/optimize-images.mjs` and run:

  ```bash
  npx --yes -p sharp@0.34 node scripts/optimize-images.mjs
  ```

  This writes WebP variants to `client/public/assets/img/` and regenerates the manifest. Commit both.
  The build doesn't need `sharp`.
* **`sizes` must describe the rendered CSS width.** Pack shots are height-constrained with
  `object-fit: contain`, so their rendered width is `slot height × aspect ratio`. `packSizes()` in
  `components/ProductCard.tsx` computes that for you.
* **Only the real LCP image gets `priority`** (`fetchpriority="high"`, not lazy). On the homepage
  that's the hero photo. Phones (≤900px) get a native-resolution centre crop in AVIF or WebP.
  The layout only ever shows that strip, so it looks identical.
* **Hero carousel:** only the slides in view download. The next slide is fetched when the
  browser is idle after load. Slides not yet needed keep their real `src` and `alt` in the HTML,
  which crawlers read, but a transparent placeholder `<source>` stops the browser fetching them.

## Fonts

* Self-hosted WOFF2 in `client/public/fonts/`, latin subset, only the faces the site actually
  renders: Poppins 400/500/600/700, Playfair Display 700 and Dancing Script 500.
* `client/src/styles/fonts.css` also declares **metric-matched fallback faces**
  (`size-adjust`, `ascent-override`, …). Text therefore takes the same space before and after the
  web font loads, so there's no font-swap layout shift.
* Only Poppins 400 and Playfair Display 700 are preloaded (`client/index.html`).
* To change weights or families, edit `FACES` in `scripts/build-fonts.py` and run it against a
  checkout of https://github.com/google/fonts (`pip install fonttools brotli`). Then update the
  two preload URLs in `client/index.html`.

## CSS & JavaScript

* There's one stylesheet: `styles/fonts.css`, then `styles/site-base.css` (the former
  `/assets/styles_623833ab.css`), then `index.css`, then `contact-navigation.css`, all imported
  by `entry-client.tsx`. The Express SSR layer (`server/_core/vite.ts`) **inlines** that stylesheet
  into the HTML (~17 KB gzipped), so first paint doesn't wait for a CSS request.
* The same step marks the app's module scripts `fetchpriority="low"`. The HTML is fully
  server-rendered, so the JS (hydration) shouldn't compete with the hero image and fonts on slow
  connections.
* **Route splitting:** the homepage is in the main bundle, and every other page is in the lazy
  `pages/HipaPages` chunk (`client/src/routes.ts`). The server awaits the chunk before rendering,
  and the browser loads it *before* hydrating non-home URLs, so hydration always matches.
* Admin pages and the chat panel are lazy chunks too. The chat panel loads on first hover or
  click of its button.
* Production source maps are enabled (`vite.config.ts`). They only describe client code that
  already ships. No secrets are bundled; server code is built separately.

## Accessibility & semantics

* One `<h1>` per page, then `<h2>` sections, then `<h3>` inside them. Don't pick heading levels for
  their size. Style a `<p>` instead (see `.feature-title`, `.footer-heading`).
* Interactive targets must be at least 24×24px. The carousel dots draw a small dot in `::before`
  inside a 24px button.
* Form fields are tied to their labels with `useId()` (`EnquiryForm.tsx`).
* The viewport meta must not disable zoom.

## AI agents / crawlers

* `/llms.txt` is generated by `buildLlmsTxt()` in `server/seoRoutes.ts`, following the llmstxt.org
  format. It only links canonical, indexable pages plus published blog posts, and
  `server/llms-txt.test.ts` enforces that.
